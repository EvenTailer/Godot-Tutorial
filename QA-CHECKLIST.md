# QA-чеклист — ручная проверка сайта

Документ для команды тестировщиков: что проверять перед релизом и как это делать.
Автоматические проверки живут отдельно (`npm run verify`) и не заменяют этот список:
они не видят, как страница выглядит и ощущается.

---

## 0. Подготовка

```bash
npm install
npm run dev            # http://localhost:5173
npm run verify         # типы, линтер, примеры, справочник ошибок, ссылки, сборка, бюджет
```

Для проверок, требующих движка: `GODOT_BIN=<путь к godot.exe> npm run verify:godot`.

> Если браузер не открывает `localhost` (страница отдаёт 502, а `curl` отвечает 200) —
> проверяй через `npm run build && npm run preview -- --port 4174` и прогоняй маршруты
> headless-браузером с отладочным портом (CDP). Признак: в консоли пусто, `document.body`
> пустой, а `Invoke-WebRequest` отдаёт 200.

## 2. Ручной обход маршрутов

Маршруты (HashRouter — адрес вида `http://localhost:5173/#/…`):

`/` · `/roadmap` · `/plan` · `/ladder` · `/cheatsheets` · `/errors` · `/versions` ·
`/resources` · `/glossary` · `/faq` · `/stage/00-sreda-redaktor-git` ·
`/stage/03-2d-dvizhenie-i-fizika` · `/stage/12-finalnyy-proekt` · несуществующий маршрут (404)

По каждому маршруту:

- [ ] открывается, есть один `h1`, заголовки идут без пропусков уровней;
- [ ] вкладка браузера: заголовок соответствует странице;
- [ ] `meta description` соответствует странице, не остался от предыдущей;
- [ ] в консоли нет ошибок;
- [ ] все ссылки ведут на существующие места, у всех читаемое название;
- [ ] зоны нажатия не меньше 44px (кроме ссылок внутри абзацев);
- [ ] нет «пустых» блоков: схемы, код, таблицы отрисовались.

## 3. Функциональные сценарии

### Прогресс обучения
- [ ] отметка темы/шага/задания сохраняется после перезагрузки;
- [ ] полоса прогресса и надпись «N из M» обновляются сразу;
- [ ] на главной кнопка «Продолжить» ведёт на первый незакрытый пункт (проверить `location.hash` и наличие элемента с таким `id`);
- [ ] «Сбросить прогресс» в подвале очищает отметки по подтверждению;
- [ ] после сброса **тема не сбрасывается**.

### Поиск
- [ ] запрос «сигнал» находит темы, примеры и статьи справочника;
- [ ] совпадения подсвечены (`<mark>`), в том числе в многословных запросах;
- [ ] «ёлка» находит «елка»;
- [ ] Enter открывает выбранный результат, стрелки перебирают;
- [ ] абсурдный запрос даёт понятное пустое состояние, а не пустой список.

### Справочник ошибок (`/errors`)
- [ ] поиск по тексту ошибки (например, «nil») сужает выдачу;
- [ ] чипы-фильтры по типам работают, счётчики совпадают;
- [ ] ссылка «этап NN» на карточке открывает нужный этап;
- [ ] сообщение движка в карточке совпадает с тем, что пишет Godot.

### Страница этапа
- [ ] оглавление содержит все разделы страницы;
- [ ] переход по оглавлению не уводит на 404 и прокручивает к разделу;
- [ ] активный раздел подсвечен при прокрутке;
- [ ] у каждого блока кода есть «Скачать», у этапа — «Скачать все примеры (.md)»;
- [ ] скачанный файл открывается и содержит ровно тот код, что на странице.

### Тема, печать, версии
- [ ] переключатель темы меняет оформление и сохраняет выбор;
- [ ] «Печать / PDF» даёт читаемый документ: без шапки, с кодом и таблицами;
- [ ] страница `/versions` показывает изменения 4.5–4.7 и что делать при переходе.

## 4. Доступность

- [ ] Lighthouse: accessibility 1.0 в светлой и тёмной темах;
- [ ] клавиатурой проходится весь путь: Tab → Enter → Esc, фокус всегда виден;
- [ ] ссылка «Перейти к содержимому» работает и не ломает маршрут;
- [ ] при `prefers-reduced-motion: reduce` контент виден сразу, без анимаций;
- [ ] цвета диаграмм не «чёрные» (проверка: `getComputedStyle(el).fill !== 'rgb(0, 0, 0)'`);
- [ ] на 360px ничего не вылезает за экран, таблицы прокручиваются.

---

## 5. Как завести баг

Формат: `ISS-XXX | приоритет | статус | суть | где исправлено`
(см. ISSUES.md). Приоритет: **Blocker** (релиз невозможен), **Major** (ломает требование),
**Minor** (качество).

К багу приложи: маршрут, шаги воспроизведения, ожидаемое и фактическое поведение,
скриншот или выдержка из консоли.
