# DECISIONS.md — решения проекта «Godot 4: пошаговое руководство»

Формат записи: `D-XXX | дата | решение | причина | последствия`.
Отклонения от требований фиксируются в [ISSUES.md](./ISSUES.md).

Целевая версия Godot: **4.3 / 4.4**. Где API менялся — в интерфейсе стоит пометка версии.

---

## D-001 | 2026-10-21 | Стек: React 19 + TypeScript 5.9 + Vite 7 + Tailwind 3.4 + shadcn/ui-подход

**Решение.** React 19, TypeScript в strict-режиме, Vite 7, Tailwind CSS 3.4, компоненты в стиле
shadcn/ui (`src/components/ui/*`, `cn()` через clsx + tailwind-merge, `cva` для вариантов).

**Причина.** Стек задан в требованиях. shadcn/ui — не рантайм-библиотека, а исходники в репозитории,
поэтому «расширения стека» фактически нет: компоненты копируются в проект.

**Последствия.** Дизайн-токены живут в CSS-переменных (`src/index.css`), Tailwind лишь ссылается на них.

---

## D-002 | 2026-10-21 | shadcn/ui-примитивы строятся на нативных HTML-элементах, Radix — только `@radix-ui/react-slot`

**Решение.** Вместо полного набора Radix-пакетов используем нативные элементы:
`<details>`/`<summary>` для аккордеона, `<dialog>` для модалки и drawer, нативный `input[type=checkbox]`
для чекбоксов, нативные кнопки с `aria-expanded`/`aria-selected` для табов.
Из Radix оставлен только `@radix-ui/react-slot` (паттерн `asChild`).

**Причина.** Бюджет бандла — < 250 KB gzip. Полный shadcn/ui с Radix-примитивами (Dialog, Tabs, Accordion,
Tooltip, Popover, Select, ScrollArea, DropdownMenu, Checkbox, Switch, Slider, Toast) даёт ~90–120 KB gzip
только на примитивы. Нативные элементы дают ту же доступность (фокус, клавиатура, ARIA) бесплатно.

**Последствия.** Нет сторонних библиотек для UI. Все состояния (focus-visible, disabled, aria)
реализованы вручную — это проверяется Критиком вручную с клавиатуры.

## D-003 | 2026-10-21 | Маршрутизация: `HashRouter` + относительный `base: './'`

**Решение.** `react-router-dom` v7 в режиме `HashRouter`, в `vite.config.ts` — `base: './'`.

**Причина.** Сайт статический и должен работать офлайн, в том числе открытием `dist/index.html`
двойным щелчком, а также на любом статическом хостинге без настроек редиректов (GitHub Pages,
`file://`, открытая папка). BrowserRouter требует rewrite-правил на сервере.

**Последствия.** URL вида `/#/stage/03-2d-movement`. Приватность URL не страдает, деплой упрощается.

## D-004 | 2026-10-21 | Контент — типизированные TS-модули в `src/content/stages/*.ts`

**Решение.** Один модуль на этап, единая схема из `src/content/types.ts`.
Компоненты не содержат «текста» — только рендерят поля.

**Причина.** Godot-команда должна править текст, код-примеры и задания, не трогая вёрстку.

**Последствия.** Тип ошибётся, если поле забыли. Это осознанный барьер качества.

---

## D-005 | 2026-10-21 | Прогресс в `localStorage`, ключ `godot-plan:v1:<stageId>:<itemId>`

**Решение.** Один ключ на каждый «пункт отметки»: тема, шаг, задание, критерий, мини-проект.
Отдельный ключ `godot-plan:v1:theme` для темы, `godot-plan:v1:meta` для служебного.

**Причина.** Требование задаёт формат ключа. Пункт-уровень (а не этап-уровень) даёт точный
кольцевой прогресс и переживает перезагрузку без синхронизации с сервером.

**Последствия.** Запись идёт по событию, а не в `useEffect`-цикле на каждое изменение состояния.
Все обращения обёрнуты в try/catch: в приватном режиме браузера `localStorage` может бросить.

## D-006 | 2026-10-21 | Подсветка кода — собственный минимальный токенайзер GDScript

**Решение.** Свой лексер (~70 строк) в `src/lib/highlight.ts`: комментарии, строки, ключевые слова,
числа, аннотации `@onready`/`@export`, встроенные типы, функции.

**Причина.** Prism/highlight.js + языковой пакет GDScript — 30–60 KB gzip. Требования: бандл < 250 KB gzip,
подсветка не входит в список «тяжёлых» задач и не должна съедать бюджет.

**Последствия.** Подсветка покрывает основные случаи, но не «знает» весь язык.
Вывод кода экранируется — HTML не интерпретируется.

## D-007 | 2026-10-21 | Поиск — собственный клиентский индекс

**Решение.** Индекс строится из контента (`src/lib/search.ts`): этапы, темы, шпаргалки, FAQ, глоссарий.
Нормализация регистра и `ё`, разбиение на слова, ранжирование (совпадение в заголовке > в тексте),
подсветка совпадений в выдаче.

**Причина.** Внешний поиск (FlexSearch, Fuse) не нужен: объём контента — десятки тысяч символов,
полный перебор в памяти занимает меньше миллисекунды.

**Последствия.** Нулевые сетевые запросы, работа офлайн, предсказуемое поведение.

---

## D-008 | 2026-10-21 | Диаграммы — inline SVG React-компоненты, единый набор токенов

**Решение.** Каждая диаграмма — компонент в `src/components/diagrams/`, рисуется общим словарём
(`<Node>`, `<Edge>`, `<Label>`), палитра берётся из CSS-переменных темы. Растровых файлов нет.

**Причина.** Требование «только вектор, без внешних ссылок на изображения». Inline SVG даёт
перекраску под тему, отсутствие лишних HTTP-запросов и доступность через `<title>`/`<desc>`.

**Последствия.** Диаграмма не «весит» отдельно — она часть бандла. Из-за этого диаграммы
вынесены в `React.lazy` по маршрутам, чтобы не попадать в первый экран.

---

## D-009 | 2026-10-21 | Компромисс «диаграммы читаются при 360px» vs «страница грузится мгновенно»

**Решение.** При ширине окна < 768px диаграмма не сжимается ниже `minWidth` (480–640 px в зависимости
от сложности), а прокручивается горизонтально внутри контейнера. Под диаграммой всегда идёт
HTML-подпись и легенда, которые передают смысл словами.

**Причина.** Требования «читаются при 360px» и «бандл < 250 KB gzip» не конфликтуют напрямую,
но сжатие сложной схемы до 360px делает подписи нечитаемыми (шрифт 7px). Скролл сохраняет
читаемость; HTML-подпись страхует от потери информации.

**Последствия.** Явно зафиксированный компромисс в пользу пользователя. На десктопе диаграмма
вписывается по ширине контейнера без скролла.

## D-010 | 2026-10-21 | Скриншоты редактора — только заглушки с пометкой

**Решение.** Компонент `ScreenshotStub` рисует векторную схему «области редактора» с подписью
«здесь будет скриншот» и точной инструкцией вида «Кликните правой кнопкой → Add Child Node».

**Причина.** Требование: не выдавать сгенерированные картинки за реальные скриншоты. Настоящие
скриншоты требуют лицензионно чистых ассетов Godot и устаревают с каждой версией.

**Последствия.** 0 растровых изображений на сайте. Заглушки содержат инструкцию, а не декорацию.

## D-011 | 2026-10-21 | Тема: class + `prefers-color-scheme` + инлайн-скрипт против «мигания»

**Решение.** Тема хранится в `godot-plan:v1:theme`; при отсутствии — берётся системная.
Инлайн-скрипт в `index.html` ставит класс `dark` до первой отрисовки.

**Причина.** Иначе при перезагрузке в тёмной теме виден белый кадр (FOUC) — это ломает
восприятие «инструмента», которым пользуются по часу.

**Последствия.** `<meta name="theme-color">` фиксирован на тёмный — принимаем небольшое расхождение
с темой на мобильных браузерах.

## D-012 | 2026-10-21 | Печать в PDF — `window.print()` + `@media print`

**Решение.** Отдельная кнопка «Печать / PDF» вызывает системный диалог печати.
Стили печати: скрыть навигацию и кнопки, раскрыть все `<details>`, убрать тени, чёрный текст на белом.

**Причина.** Требование «печать в PDF» без внешних библиотек. Генерация PDF на клиенте требует
 heavyweight-зависимость (jsPDF), что ломает бюджет бандла.

**Последствия.** Читатель выбирает «Сохранить как PDF» в диалоге печати. Формат A4, поля 16mm.

## D-013 | 2026-10-21 | Верификация GDScript: godot headless `--check-only` + ClassDB

**Решение.** Все примеры кода автоматически проверяются скриптом `scripts/verify-godot-examples.mjs`:
он извлекает код из `src/content/stages/*.ts` и прогоняет через
`godot --headless --check-only --script <file>`. Дополнительно рантайм-проверка через `ClassDB`
(существование классов и методов) для спорных API.

**Причина.** Техническая точность — главный риск проекта. Сверка с бинарником Godot 4.7.2 (Steam)
надёжнее, чем чтение документации глазами: ошибка в имени метода ломает 25+ примеров.

**Последствия.** В `DECISIONS.md` есть раздел «Проверено / не проверено».

## D-014 | 2026-10-21 | Порядок этапов зафиксирован, объём этапа — не более 4 часов

**Решение.** Порядок 00→12 не меняется. Каждый этап: 4–6 тем, 4–6 шагов, 2–3 примера кода,
3 задания, 1 мини-проект, 4–5 критериев, 3–5 ресурсов. Оценка 6–12 часов, растянуто на 2 недели.

**Причина.** Требование «если контент не влезает в один этап — разбить этап, а не сжимать текст».
Критерий: этап, который нельзя закрыть за вечер, разбивается.

**Последствия.** 24 недели = 12 этапов × 2 недели. Этапы 11 и 12 (релиз и финальный проект)
занимают по 2 недели с буфером на полировку.

## D-015 | 2026-10-21 | Оценка трудозатрат этапов — от «3 часа» до «14 часов»

**Решение.** Поле `hours` в типе `Stage` — реалистичная оценка «от первого открытия файла до
работающего результата», включая чтение ошибок компилятора.

**Причина.** Иначе новичок строит план по оптимистичным цифрам и бросает на третьей неделе.

**Последствия.** Сумма по этапам не равна 24 неделям × 8 часов — остаётся время на практику
и повторение. Это указано в разделе «План на 24 недели».

## D-016 | 2026-10-21 | English-термины Godot не переводятся, русский перевод — в скобках при первом упоминании

**Решение.** `Node`, `Scene`, `signal`, `_ready()`, `Inspector`, `Autoload` остаются на английском.
При первом появлении в теме — перевод в скобках: «сцена (Scene)».

**Причина.** Требование №9. Двуязычные термины повторяются по всему контенту — единообразие важнее
«полного перевода».

**Последствия.** В глоссарии эти термины собраны с переводом и ссылкой на этап, где разбираются.

---

## D-017 | 2026-10-21 | Термины Godot при первом появлении переводятся, но не дублируются в каждой теме

**Решение.** Перевод даётся в `term` поля `Topic` и в глоссарии. В тексте темы термин
используется без перевода, если он уже встречался раньше.

**Причина.** Повторный перевод каждого термина на каждом этапе превращает текст в «стену»,
что прямо запрещено требованием №10.

---

## D-018 | 2026-10-21 | «Знаю тему» = критерий + способ проверки

**Решение.** `Criterion` содержит утверждение от первого лица и способ проверки — действие,
а не описание. Например: «Могу объяснить, зачем нужен `_ready()`» → проверка: «написать новый узел
и объяснить, почему настройки стоят в `_ready`, а не в `__init__`».

**Причина.** Самопроверка без действия превращается в формальность и не работает.

## D-019 | 2026-10-21 | Мёртвых кнопок нет: любая кнопка имеет обработчик

**Решение.** В UI нет заглушек «скоро», ссылок «в разработке», декоративных иконок-кнопок.
Внешние ссылки открываются с `rel="noopener noreferrer"`, у всех — `aria-label` с типом действия.

**Причина.** Требование №4 (критик-блокер).

## D-020 | 2026-10-21 | `prefers-reduced-motion` отключает все анимации, включая кольцо прогресса

**Решение.** В `src/index.css` — глобальный `@media (prefers-reduced-motion: reduce)`,
который обнуляет `animation`/`transition`; кольцо прогресса при этом рисуется сразу конечным
состоянием, а не «докручивается».

**Причина.** Требование №5 (доступность). У пользователей с вестибулярными расстройствами
анимация кольца — источник дискомфорта.

---

## D-021 | 2026-10-21 | Каждый этап даёт работающий результат

**Решение.** У каждого этапа есть `outcome` — одно предложение вида «в редакторе есть сцена, которая
прыгает и считает очки». Это проверяется Критиком: этап без наблюдаемого результата — Major.

**Причина.** Требование фазы 1: «каждый этап даёт работающий результат, а не только знание».

---

## D-022 | 2026-10-21 | Тёмная тема — не инверсия, а отдельная палитра

**Решение.** Для тёмной темы заданы собственные значения токенов (не автоматическая инверсия),
контрастные пары проверены расчётом.

**Причина.** Инверсия даёт «грязный» синий на чёрном и проваливает контраст.

**Последствия.** Раздел «Проверено» содержит таблицу контрастов для светлой и тёмной темы.

## D-023 | 2026-10-21 | Контент в TS, но проверяется скриптом — контент и код не могут разойтись

**Решение.** `npm run verify:godot` извлекает примеры кода из контент-модулей и валидирует их
в Godot. Скрипт входит в CI-подобную проверку (`npm run build` его не запускает, но он запускается
вручную перед релизом и описан в README).

**Причина.** Контент и код лежат рядом — значит, могут разойтись. Автоматическая проверка
закрывает класс ошибок «метод переименовали в 4.3, а в тексте осталось 4.2».

## D-024 | 2026-10-21 | Стек не расширяется без записи сюда

**Решение.** Любая новая зависимость сначала фиксируется здесь (номер, причина, цена в бандле),
и только потом ставится в `package.json`.

**Причина.** Требование №11. Особенно важно для бандл-бюджета.

---

## D-025 | 2026-10-21 | Экраны подгружаются лениво, контент — отдельным чанком

**Решение.** Все страницы подключены через `React.lazy` + `Suspense`. Данные курса
вынесены в отдельный чанк `content` (manualChunks).

**Причина.** Изначально весь сайт собирался одним чанком на 747 KB (218 KB gzip) —
Vite предупреждал о превышении лимита, а первый экран тянул весь контент курса.

**Последствия.** Критический путь (html + css + entry + чанк маршрута) — 91 KB gzip.
Полный набор файлов сборки — 249.93 KB gzip. Ни один чанк не превышает 500 KB.
Индикатор загрузки — скелетон с `aria-busy` и `aria-live`.

## D-026 | 2026-10-21 | Поиск — обычный список ссылок, без роли combobox

**Решение.** Поле поиска — нативный `input[type=search]`, панель результатов — `<ul>`
со ссылками, подсказка — `aria-describedby`, счётчик результатов — живой регион.

**Причина.** Первый вариант использовал `role="combobox"` / `role="listbox"` /
`role="option"` с `<ul>` внутри `listbox`. axe (Lighthouse) фиксировал
`aria-required-children` и `aria-required-parent`: ARIA-роли применены неверно.

**Последствия.** Нет нарушений ARIA, клавиатура работает (стрелки + Enter + Escape),
подсветка совпадений сохранена.

---

## D-027 | 2026-10-21 | Контраст токенов подобран по Lighthouse, а не на глаз

**Решение.** Цвета `info` и `warning` затемнены в светлой теме до прохождения
контраста 4.5:1 на собственном фоне бейджа. В тёмной теме значения не менялись.

**Причина.** Первая версия палитры давала 4.07:1 (`text-info`) и 4.44:1 (бейдж
`warning`) — оба ниже порога WCAG AA.

**Последствия.** Lighthouse: accessibility 1.0 в светлой и тёмной темах.
Тёмная тема задана отдельной палитрой, а не инверсией (см. D-022).

---

## D-028 | 2026-10-21 | Зона нажатия не меньше 44px

**Решение.** Все интерактивные элементы (кнопки, иконки, вкладки, чекбоксы,
переключатели, ссылки навигации, копирование кода, раскрывающиеся подзаголовки)
имеют высоту не меньше 44px.

**Причина.** Требование доступности: «размеры тапов ≥ 44px».

**Последствия.** Чуть плотнее шапка, зато попасть пальцем можно без промаха.

---

## D-029 | 2026-10-21 | Бюджет сборки: 249.93 KB gzip — впритык, и это осознанно

**Решение.** Бюджет «< 250 KB gzip» трактуется как сумма всех файлов сборки.
Сейчас — 249.93 KB. Критический путь — 91 KB gzip.

**Причина.** Сайт-гайд — это в первую очередь текст: 13 этапов, 37 примеров кода,
38 терминов глоссария, 15 вопросов FAQ, 4 шпаргалки. Сам корпус в сжатом виде —
около 105 KB gzip, и сократить его без потери педагогической ценности нельзя.
Осознанные сокращения уже сделаны: убрано дублирование данных (быстрые проекты
теперь выводятся из этапов), из подсветчика удалены 57 редких имён.

**Последствия.** Любое добавление контента требует повторного замера:
`node scripts/measure-bundle.mjs`. Если сумма превысит лимит — приоритет у
сокращения второстепенных текстов, а не у качества примеров кода.

---

## D-030 | 2026-10-21 | Быстрые проекты не дублируются в контенте

**Решение.** Список «проекты внутри этапов» строится из данных этапов
(`stage.project.title`, `stage.hours`), а не хранится отдельным массивом.

**Причина.** Дублирование данных — источник расхождений: при переименовании
мини-проекта в этапе отдельный список остался бы старым.

**Последствия.** Минус ~1.5 KB в сборке, контент всегда синхронен.

## D-031 | 2026-10-21 | Файлы скриптов проверки живут в репозитории

**Решение.** `scripts/verify-godot-examples.mjs` (проверка примеров кода) и
`scripts/measure-bundle.mjs` (замер бандла) — часть проекта и запускаются из npm-скриптов.

**Причина.** Проверка кода — единственный способ удержать техническую точность
при правках контента. Если её нет в репозитории, она исчезнет при первом же
переносе проекта.

**Последствия.** `npm run verify:godot` требует установленного Godot; без него
скрипт честно сообщает об этом и завершается с кодом 2.
